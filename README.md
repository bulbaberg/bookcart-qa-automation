# BookCart QA Automation

## О проекте автоматизации
BookCart — open-source веб-приложение интернет-магазина книг. Пользователь может искать и просматривать книги, добавлять их в корзину, оформлять заказы и просматривать историю заказов. Администратору доступно управление каталогом книг.

Исходный код - https://github.com/AnkitSharma-007/bookcart

BookCart QA Automation — учебно-портфолио проект по автоматизации тестирования этого приложения.

Проект построен на Java и включает в себя отдельные UI, API и DB-автотесты, а также сквозные проверки между несколькими уровнями приложения.

Основная цель проекта — показать практическую работу с автоматизацией тестирования и понимание взаимодействия между frontend, backend, API и базой данных.

## Архитектура приложения
BookCart состоит из нескольких основных уровней:

Browser → Angular frontend → REST API → .NET backend → SQL Server

## Стек
- Java - основной язык автоматизации;
- JUnit - организация и запуск автотестов;
- Selenide - автоматизация UI в браузере;
- REST Assured - автоматизация REST API;
- JDBC - работа с базой данных из Java;
- SQL Server - база данных тестируемого приложения;
- Maven - управление зависимостями и запуск тестов;
- Allure - формирование отчётов о выполнении тестов;
- Git - контроль версий.

## Покрытие автотестами

### UI-тесты
- успешная авторизация пользователя;
- проверка ошибки при неверном пароле;
- регистрация нового пользователя - временно отключена из-за известного дефекта приложения;
- создание книги;
- изменение данных книги;
- удаление книги;
- просмотр карточки книги;
- поиск книги;
- добавление книги в корзину;
- проверка товара в корзине;
- оформление заказа;
- проверка созданного заказа;
- проверка требований к паролю при регистрации.

### API-тесты
- успешная авторизация и получение JWT;
- проверка ошибки авторизации;
- валидация username при регистрации;
- регистрация нового пользователя - временно отключена из-за известного дефекта приложения;
- получение списка книг;
- поиск конкретной книги;
- создание, изменение и удаление книги;
- проверка запрета создания книги без авторизации;
- добавление книги в корзину;
- получение и очистка корзины;
- создание заказа;
- получение и проверка заказа;
- полный API-сценарий: создание тестовой книги, добавление её в корзину, оформление заказа и проверка созданного заказа через Orders API.

### DB-тесты
- проверка подключения к SQL Server через JDBC;
- проверка сохранения созданной через API книги в Book;
- получение данных заказа из таблиц CustomerOrders и CustomerOrderDetails.

### Сквозные тесты
- создание книги через API и проверка её сохранения в базе данных через JDBC;
- подготовка уникальной тестовой книги через API, покупка книги через UI, поиск созданного заказа в базе данных и финальная проверка этого заказа на странице My Orders.

## Структура проекта

```text
src/test/java
│
├── config
│   └── TestConfig.java
│
├── data
│   ├── BookData.java
│   ├── CreatedBook.java
│   ├── LoginData.java
│   └── RegisterData.java
│
├── helpers
│   ├── ApiBookHelper.java
│   ├── ApiLoginHelper.java
│   ├── ApiShoppingCartHelper.java
│   ├── OrderDbHelper.java
│   └── RequestSpecFactory.java
│
├── pages
│   ├── ...
│   └── components
│       └── Header.java
│
└── tests
    ├── api
    ├── db
    └── ui
```
Назначение: 
- config — конфигурация тестового окружения;
- data — тестовые данные и объекты для передачи данных между шагами;
- helpers — переиспользуемые операции для API, подготовки тестовых данных и работы с БД;
- pages — Page Object и Page Component для взаимодействия с UI;
- tests/api — API-автотесты;
- tests/db — проверки базы данных через JDBC;
- tests/ui — UI-автотесты на Selenide.

## Требования к окружению
Для локального запуска BookCart и автотестов требуется следующее окружение:
- .NET SDK 9 - запуск ASP.NET Core backend;
- Node.js 22 LTS - запуск Angular frontend;
- npm - установка frontend-зависимостей и запуск frontend;
- SQL Server - база данных BookCart;
- Java 21 - запуск automation-проекта;
- Maven - сборка проекта и запуск автотестов;
- Allure CLI — локальная генерация и просмотр Allure Report.

## Запуск приложения
Для выполнения автотестов приложение BookCart должно быть запущено локально.

BookCart состоит из двух отдельно запускаемых частей:
- ASP.NET Core backend;
- Angular frontend.

Также должна быть доступна база данных BookCart в SQL Server.

### Backend

Перейти в каталог backend приложения BookCart и выполнить в командной строке:

```cmd
dotnet run --project BookCart.csproj
```

После запуска backend доступен по адресу:

`https://localhost:7073`

Swagger:

`https://localhost:7073/swagger`

### Frontend

В отдельной командной строке перейти в каталог frontend:

`BookCart/ClientApp`

Указать HTTPS-порт backend для Angular proxy:

```cmd
set ASPNETCORE_HTTPS_PORT=7073
```

Запустить frontend:

```cmd
npm start
```

После запуска frontend доступен по адресу:

`https://localhost:53424`

## Запуск автотестов
Перед запуском автотестов должны быть запущены frontend, backend и SQL Server с базой данных BookCart. 

Пароль пользователя базы данных не хранится в исходном коде и передаётся через переменную окружения: `BOOKCART_DB_PASSWORD`

Для запуска полного набора автотестов выполнить:

```cmd
mvn clean test
```

## Allure Report
Для формирования отчётов о выполнении автотестов используется Allure Report.

После запуска тестов результаты сохраняются в каталоге: `target/allure-results`

Для генерации HTML-отчёта выполнить команду: 

```cmd
allure generate target/allure-results -o allure-report --clean
```

Для просмотра отчёта выполнить команду: 

```cmd
allure open allure-report
```

## Известные проблемы и ограничения
1. Позитивные сценарии регистрации пользователя через UI и API временно отключены (`@Disabled`). Backend возвращает `200 OK`, но новый пользователь не сохраняется в базе данных.
2. В отдельных API-тестах Shopping Cart и Checkout используется существующий `bookId` как фиксированное тестовое значение. В полном сценарии покупки и сквозных проверках тестовые книги создаются динамически через API.
